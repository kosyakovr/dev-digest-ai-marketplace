# Metadata, Viewport, and OG Images

Setting `<head>`, social images, icons, robots, sitemaps, and JSON-LD with the Next.js 16 Metadata APIs.

## Core rules

**Do**
- Export a static `metadata` object when values do not depend on request data; use `generateMetadata` only
  when they do (params, fetched data, parent metadata).
- Export them from `layout.tsx` or `page.tsx` that are **Server Components**. Need interactivity on that page?
  Keep the page on the server and move client logic into a child `'use client'` component.
- `await` `params`/`searchParams` (Promises; `searchParams` exists only for pages). `notFound()`/`redirect()` work here.
- Fetch shared data once: `fetch` calls are memoized across `generateMetadata`, `generateStaticParams`,
  layouts, and pages; wrap non-`fetch` loaders (ORM, SDK) in React `cache` (see `getRecipe` below).
- Put `themeColor`, `colorScheme`, and scale in a `viewport`/`generateViewport` export (deprecated in `metadata`).
- Set `metadataBase` in the root layout; relative URL fields (`openGraph`, `alternates`) without it fail the build.

**Avoid**
- Exporting both `metadata` and `generateMetadata` (or both `viewport` and `generateViewport`) from one segment.
- Hand-writing `<title>`/`<meta>` in layouts (the API handles dedupe and streaming).
- Assuming nested objects merge: segments merge **shallowly**, so a page that sets `openGraph` replaces the
  layout's whole `openGraph` (spread a shared constant to keep common fields).

```tsx
// app/recipes/[slug]/page.tsx
import type { Metadata } from 'next'
import { notFound } from 'next/navigation'
import { getRecipe } from '@/lib/recipes' // = cache((slug: string) => db.recipe.findUnique(...))

export async function generateMetadata(props: PageProps<'/recipes/[slug]'>): Promise<Metadata> {
  const { slug } = await props.params
  const recipe = await getRecipe(slug)
  if (!recipe) notFound()
  return { title: recipe.name, description: recipe.summary, alternates: { canonical: `/recipes/${slug}` } }
}
export default async function RecipePage(props: PageProps<'/recipes/[slug]'>) {
  const recipe = await getRecipe((await props.params).slug) // same call, runs once per request
  return <h1>{recipe?.name}</h1>
}
```

## Titles and the root layout

```tsx
// app/layout.tsx (excerpt)
import type { Metadata, Viewport } from 'next'
export const metadata: Metadata = {
  metadataBase: new URL('https://recipes.example'),
  title: { template: '%s | Pantry', default: 'Pantry' }, // a default is required with a template
}
export const viewport: Viewport = { themeColor: '#14532d' }
```

- `title.template` applies to **child** segments only (not its own segment; no effect in a page).
  A child opts out with `title: { absolute: '...' }`.
- When `generateMetadata` uses `'use cache'`, return `metadataBase` as a string (`URL` is not serializable).

## Streaming and Cache Components

- On dynamically rendered pages, metadata from `generateMetadata` streams in after the UI (tags are appended
  to `<body>`). Prerendered pages resolve it at build time, so nothing streams.
- HTML-limited bots (detected by User-Agent, e.g. Twitterbot, Slackbot, Bingbot) still get blocking metadata in
  `<head>`. `htmlLimitedBots` in `next.config.ts` replaces the default list; `/.*/` disables streaming metadata
  entirely. Leave the default unless a specific crawler misbehaves (recommendation).
- With `cacheComponents: true`: if `generateMetadata` reads runtime data (`cookies()`, `headers()`, `params`,
  `searchParams`) or does uncached fetching while the rest of the page is fully prerenderable, Next.js raises an
  error. Fix: `'use cache'` in `generateMetadata` (external data only), or a Suspense-wrapped component that
  awaits `connection()` to mark the page intentionally dynamic. Viewport cannot stream: a dynamic
  `generateViewport` needs `'use cache'`, `<Suspense>` around the body, or `instant = false` ([data-patterns.md](data-patterns.md)).

## File-based metadata (overrides `metadata` / `generateMetadata`)

| File | Where | Notes |
| --- | --- | --- |
| `favicon.ico` | `app/` root only | Cannot be generated by code |
| `icon.(ico,jpg,jpeg,png,svg)` / `icon.tsx` | any segment | `icon1.png`, `icon2.png` for several |
| `apple-icon.(jpg,jpeg,png)` / `apple-icon.tsx` | any segment | |
| `opengraph-image` / `twitter-image` (`.jpg,.jpeg,.png,.gif` or `.tsx`) | any segment | Optional `*.alt.txt`; static files over 8MB (OG) / 5MB (Twitter) fail the build |
| `robots.txt` / `robots.ts` | `app/` root | Return `MetadataRoute.Robots` |
| `sitemap.xml` / `sitemap.ts` | any segment | Return `MetadataRoute.Sitemap`; split with `generateSitemaps` |
| `manifest.json` / `manifest.webmanifest` / `manifest.ts` | `app/` root | Return `MetadataRoute.Manifest` |

Generated variants are special Route Handlers, cached by default unless they use Request-time APIs or uncached
data. Exclude metadata files from your proxy `matcher` ([file-conventions.md](file-conventions.md)).

**Next.js 16 breaking changes**: the default export of `opengraph-image`, `twitter-image`, `icon`, and
`apple-icon` receives `params` **and** `id` as Promises; `generateImageMetadata` itself still gets plain
`params`. The `sitemap` function receives `id` (from `generateSitemaps`) as a `Promise<string>`.

```tsx
// app/recipes/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'
import { getRecipe } from '@/lib/recipes'
export const size = { width: 1200, height: 630 }
export const contentType = 'image/png'
export const alt = 'Recipe card'
export default async function OgImage({ params }: { params: Promise<{ slug: string }> }) {
  const recipe = await getRecipe((await params).slug)
  const style = { display: 'flex', width: '100%', height: '100%', alignItems: 'center', padding: 64, fontSize: 72 }
  return new ImageResponse(<div style={style}>{recipe?.name ?? 'Pantry'}</div>, size)
}
```

```ts
// app/recipes/sitemap.ts
import type { MetadataRoute } from 'next'
import { countRecipes, listRecipeSlugs } from '@/lib/recipes'
export async function generateSitemaps() {
  return Array.from({ length: Math.ceil((await countRecipes()) / 50_000) }, (_, id) => ({ id }))
}
export default async function sitemap({ id }: { id: Promise<string> }): Promise<MetadataRoute.Sitemap> {
  const slugs = await listRecipeSlugs({ offset: Number(await id) * 50_000, limit: 50_000 })
  return slugs.map((s) => ({ url: `https://recipes.example/recipes/${s}` }))
} // served at /recipes/sitemap/<id>.xml
```

`ImageResponse` limits: flexbox and a CSS subset only (no `display: grid`); default 1200x630; fonts must be
`ttf`, `otf`, or `woff` (prefer `ttf`/`otf`); 500KB bundle cap including JSX, CSS, fonts, and images. Load
fonts or logos once at module scope.

## JSON-LD

Render a native `<script type="application/ld+json">` in a page or layout (not `next/script`); escape `<`:

```tsx
// app/recipes/[slug]/recipe-json-ld.tsx
export function RecipeJsonLd({ name, image }: { name: string; image: string }) {
  const data = { '@context': 'https://schema.org', '@type': 'Recipe', name, image }
  return <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(data).replace(/</g, '\\u003c') }} />
}
```
