# File Conventions (App Router)

How folders and special files under `app/` map to URLs and UI, plus the top-level files (`proxy.ts`,
`instrumentation.ts`, `public/`, `src/`) that Next.js 16 recognizes.

## Special files in a route segment

| File | Purpose | Notes |
| --- | --- | --- |
| `layout.tsx` | Shared UI; keeps state across navigations | Root layout is required and must render `<html>` and `<body>` |
| `page.tsx` | Makes the segment publicly routable | Innermost file in the hierarchy |
| `route.ts` | HTTP endpoint (see [route-handlers.md](route-handlers.md)) | Cannot sit in the same segment as `page.tsx` |
| `loading.tsx` | Suspense fallback for the segment | See [suspense-boundaries.md](suspense-boundaries.md) |
| `error.tsx` | Error boundary for the segment | Must be a Client Component (`'use client'`) |
| `global-error.tsx` | Replaces the root layout when it fails | Must render its own `<html>` and `<body>` |
| `not-found.tsx` | UI for `notFound()` | |
| `forbidden.tsx` / `unauthorized.tsx` | UI for `forbidden()` / `unauthorized()` | Experimental; need `experimental.authInterrupts` |
| `template.tsx` | Like a layout, but remounts on navigation | Use only when you need a reset |
| `default.tsx` | Fallback for a parallel-route slot | See [parallel-routes.md](parallel-routes.md) |

Rendering order inside one segment, outermost first: `layout` -> `template` -> `error` -> `loading` ->
`not-found` -> `page` (or the child segment's `layout`). Child segments nest inside the parent's tree, so an `error.tsx`
does not catch errors thrown by the `layout.tsx` in the same folder; place it one level up (or rely on
`global-error.tsx` for the root). Details: [error-handling.md](error-handling.md).

**Do**
- Let the Metadata API own `<head>`; do not hand-write `<title>`/`<meta>` in the root layout ([metadata.md](metadata.md)).
- Reach for `template.tsx` only to re-run effects, reset client state, or show a Suspense fallback on every
  navigation. A template remounts when its own segment (including its dynamic params) changes; search param
  changes do not remount it.
- In `error.tsx`, prefer the `retry` prop (stable since 16.3) over `reset`; `reset` clears state without re-fetching.

**Avoid**
- Treating every folder as a page: a folder only becomes a route once it contains `page.tsx` or `route.ts`, and
  only what those files return is sent to the client.

## Dynamic segments

| Folder | Matches | `params` type |
| --- | --- | --- |
| `app/tickets/[id]` | `/tickets/42` | `{ id: string }` |
| `app/recipes/[...path]` | `/recipes/soup`, `/recipes/soup/cold` (not `/recipes`) | `{ path: string[] }` |
| `app/shelf/[[...path]]` | also `/shelf` itself | `{ path?: string[] }` |

`params` is a Promise in `page`, `layout`, `route`, and `generateMetadata`. Await it in Server Components or
unwrap it with React `use()` in a Client Component page. The global helpers `PageProps<'/route'>`,
`LayoutProps<'/route'>`, and `RouteContext<'/route'>` type it for you (generated by `next dev`, `next build`,
or `next typegen`).

```tsx
// app/tickets/[id]/page.tsx
import { notFound } from 'next/navigation'
import { getTicket } from '@/lib/tickets'

export default async function TicketPage(props: PageProps<'/tickets/[id]'>) {
  const { id } = await props.params
  if (!/^\d+$/.test(id)) notFound() // params are user input; validate them
  const ticket = await getTicket(Number(id))
  return <h1>{ticket.title}</h1>
}
```

With `cacheComponents: true`, a param that is not covered by `generateStaticParams` is runtime data: read it
inside a `<Suspense>` boundary (or under `loading.tsx`). In layouts, pass the `params` promise down instead of
awaiting it at the top so the layout can still be prerendered. See [async-patterns.md](async-patterns.md).

## Organizing without changing URLs

- **Route groups** `(name)`: omitted from the URL. Use them to share a layout among some routes, scope a
  `loading.tsx` to one page, or create multiple root layouts (each must render `<html>`/`<body>`).
  Navigating between different root layouts causes a full page load. Two groups must not resolve to the same
  path (`(shop)/about` plus `(site)/about` causes an error).
- **Private folders** `_name`: the folder and everything under it is excluded from routing. Colocation is already
  safe without them; they mainly separate UI helpers from routing files and avoid clashes with future special
  names. Need a literal leading underscore in a URL? Name the folder `%5Fname`.
- **Colocation**: components, tests, and utilities can live next to `page.tsx`; they are never routable on their own.
- **`src/`**: optional. Move `app/` to `src/app/`; `proxy.ts` and `instrumentation.ts` then also live in `src/`.
  `public/`, `next.config.ts`, `package.json`, `tsconfig.json`, and `.env*` stay at the project root. If both
  `app/` and `src/app/` exist, `src/app/` is ignored. Update `tsconfig.json` `paths` (e.g. `@/*`) accordingly.

## `proxy.ts` (formerly `middleware.ts`)

Next.js 16 deprecated the `middleware` file convention and renamed it to `proxy`; behavior is otherwise the same.
One `proxy.ts` per project, at the root (or in `src/`), exporting a function named `proxy` or a default export.

```ts
// proxy.ts
import { NextResponse, type NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  if (!request.cookies.has('reader_session')) {
    return NextResponse.redirect(new URL('/sign-in', request.url))
  }
  return NextResponse.next()
}

export const config = {
  // constants only; excludes assets so CSS/JS/images are never blocked
  matcher: ['/((?!api|_next/static|_next/image|favicon.ico|robots.txt|sitemap.xml).*)'],
}
```

**Do**
- Migrate with `npx @next/codemod@canary middleware-to-proxy .` (renames file, function, and flags such as
  `skipMiddlewareUrlNormalize` -> `skipProxyUrlNormalize`).
- Always set a `matcher`; without one, proxy runs for every request including `_next/static`, `_next/image`, and `public/` files.
- Keep proxy logic to fast, optimistic checks (redirects, rewrites, headers). Re-check auth inside each Server
  Function and data access layer: Server Functions are POSTs to the page route, so a matcher that skips that
  path also skips them (see `engineering-paved-path:security`).
- Prefer `redirects`/`rewrites`/`headers` in `next.config.ts` for static rules.

**Avoid**
- Exporting `runtime` from `proxy.ts`: proxy always runs on Node.js and setting it throws an error.
- Slow data fetching or relying on module globals in proxy; `fetch` caching options have no effect there.
- Passing request headers via `NextResponse.next({ headers })` (that exposes them to the client); use
  `NextResponse.next({ request: { headers } })`.

**When `middleware.ts` is still needed:** proxy does not support the Edge runtime. The v16 upgrade guide says to
keep using `middleware.ts` if you need Edge for this layer. It still works but is deprecated; see
[runtime-selection.md](runtime-selection.md).

## Other top-level files

- `instrumentation.ts`: exports `register()` (runs once per server instance before requests are served) and
  optionally `onRequestError(err, request, context)` to report server errors. Branch on
  `process.env.NEXT_RUNTIME` if code differs between Node.js and Edge.
- `public/`: served from `/` (e.g. `public/covers/dune.png` -> `/covers/dune.png`) with
  `Cache-Control: public, max-age=0`. Put `favicon.ico`, `robots.txt`, etc. in `app/` as metadata files instead.
