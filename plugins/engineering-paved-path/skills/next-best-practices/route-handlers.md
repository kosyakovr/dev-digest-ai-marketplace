# Route Handlers

How to write `route.ts` endpoints in the App Router (Next.js 16): conventions, params, caching in both
caching modes, request/response helpers, and when a Route Handler is the wrong tool.

## Conventions

- Export named functions per HTTP verb from `app/**/route.ts`: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`,
  `HEAD`, `OPTIONS`. Any other verb gets `405 Method Not Allowed`. If you do not export `OPTIONS`, Next.js
  answers it for you with an `Allow` header listing the verbs you did export.
- A `route.ts` and a `page.tsx` **cannot** live in the same segment (`app/route.ts` + `app/page.tsx`
  conflicts; `app/api/route.ts` + `app/page.tsx` is fine). Route Handlers take no part in layouts or
  client-side navigation.
- The first argument is a `NextRequest` (a Web `Request` with `nextUrl` and `cookies`). The second is a
  context whose `params` is a **Promise** (since v15). Type it with the global `RouteContext<'/path/[id]'>`
  helper, generated by `next dev`, `next build` or `next typegen`; no import needed.

```ts
// app/api/invoices/[id]/route.ts
import { type NextRequest, NextResponse } from 'next/server'
import { notFound } from 'next/navigation'
import { getInvoiceForUser } from '@/lib/dal/invoices'

export async function GET(request: NextRequest, ctx: RouteContext<'/api/invoices/[id]'>) {
  const { id } = await ctx.params
  const format = request.nextUrl.searchParams.get('format') ?? 'json'
  const invoice = await getInvoiceForUser(id) // DAL does the auth check
  if (!invoice) notFound() // serves a 404 from a Route Handler
  return format === 'csv'
    ? new Response(invoice.toCsv(), { headers: { 'Content-Type': 'text/csv' } })
    : NextResponse.json(invoice)
}
```

## Caching GET handlers

| Mode | Default | How to make it static / cached |
| --- | --- | --- |
| Without `cacheComponents` (previous model) | Not cached; runs per request (default changed from static to dynamic in v15) | `export const dynamic = 'force-static'` or `export const revalidate = 60` |
| With `cacheComponents: true` | Same model as pages: prerendered at build if it touches no uncached/runtime data, otherwise runs at request time | Move uncached work into a helper marked `'use cache'` (+ `cacheLife`) |

- Only `GET` can be cached. `POST`/`PUT`/`PATCH`/`DELETE` are never cached, even next to a cached `GET`.
- With Cache Components, prerendering stops as soon as the handler reads `request.url`, `request.headers`,
  `request.cookies`, the body, `cookies()`, `headers()`, `connection()`, does network/DB/async FS work,
  or calls something non-deterministic such as `Math.random()`.
- `'use cache'` cannot sit directly in the handler body; put it in a helper function.
- With Cache Components, the route segment options `dynamic`, `revalidate` and `fetchCache` are removed,
  and Cache Components requires the Node.js runtime, so delete any `runtime` export (even `'nodejs'`).
  `maxDuration` still applies. See [data-patterns.md](data-patterns.md).
- `generateStaticParams` works in dynamic Route Handlers to prerender chosen params.

```ts
// app/api/recipes/route.ts  (cacheComponents: true)
import { cacheLife, cacheTag } from 'next/cache'

async function listRecipes() {
  'use cache'
  cacheLife('hours')
  cacheTag('recipes')
  return db.recipe.findMany({ orderBy: { title: 'asc' } })
}

export async function GET() {
  return Response.json(await listRecipes())
}
```

## Request and response helpers

- Read the body once with `request.json()`, `request.formData()` or `request.text()`; `clone()` the
  request if you must read it twice. `GET`/`HEAD` have no body.
- `cookies()` / `headers()` from `next/headers` work here; `headers()` is read-only, so set response
  headers on the `Response` you return. `cookies()` can also set and delete cookies.
- `NextResponse.json(body, init)`, `NextResponse.redirect(url)`, `NextResponse.rewrite(url)`; `redirect()`
  from `next/navigation` also works inside handlers.
- Streaming: return `new Response(readableStream)`; works for LLM token streams or chunked output.

```ts
// app/api/tickets/export/route.ts
export async function GET() {
  const encoder = new TextEncoder()
  const stream = new ReadableStream({
    async start(controller) {
      for await (const row of db.ticket.iterateAll()) controller.enqueue(encoder.encode(row.toCsvLine()))
      controller.close()
    },
  })
  return new Response(stream, { headers: { 'Content-Type': 'text/csv' } })
}
```

## CORS, webhooks, security

**Do**
- Set CORS headers on the returned `Response` for one handler; for many handlers use Proxy or
  `headers()` in `next.config.ts`. Define `OPTIONS` yourself when preflight needs specific CORS headers (recommendation).
- Treat every handler as a public endpoint: authenticate and authorize inside it (Proxy alone is not
  enough), validate payload type/size, rate-limit, and keep internal details out of error responses.
- Verify webhook secrets before acting, e.g. before calling `revalidateTag(tag, 'max')`.
- Validate redirect targets in callback handlers (same-origin check) before `NextResponse.redirect`.

**Avoid**
- Echoing incoming request headers into the response, or putting secrets in response headers.
- Sending sensitive data in `GET` query strings; URLs get cached and logged.
- Assuming shared in-memory state, a writable file system, WebSockets or unlimited run time on
  serverless hosts.

```ts
// app/api/cms-webhook/route.ts
import { type NextRequest, NextResponse } from 'next/server'
import { revalidateTag } from 'next/cache'

export async function POST(request: NextRequest) {
  if (request.headers.get('x-cms-secret') !== process.env.CMS_WEBHOOK_SECRET) {
    return NextResponse.json({ ok: false }, { status: 401 })
  }
  const { collection } = (await request.json()) as { collection?: string }
  if (!collection) return NextResponse.json({ ok: false }, { status: 400 })
  revalidateTag(collection, 'max') // stale-while-revalidate
  return NextResponse.json({ ok: true })
}
```

## Route Handler, Server Action, or Server Component?

- **Server Component reads data directly** from the DB/DAL. Do not `fetch` your own Route Handler from a
  Server Component: it fails at build time for prerendered routes and adds an HTTP hop otherwise.
- **Server Function (Action)** for mutations triggered by your own UI. Actions are queued, so do not use
  them for data fetching.
- **Route Handler** for external clients, webhooks, OAuth callbacks, non-HTML content (RSS, CSV,
  `llms.txt`), and client-side polling endpoints. Prefer the metadata file conventions for sitemap,
  robots, icons and OG images. In `output: 'export'`, only `GET` with `dynamic = 'force-static'` works.
